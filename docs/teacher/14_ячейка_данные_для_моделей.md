# Ячейка «данные для моделей этапа 3» (ноутбук exp3) построчно

Эта ячейка готовит таблицу, на которой обучаются все модели этапа 3 (Cox, дерево и лес выживаемости). Она выбирает признаки, убирает непригодные строки, делит людей на train и test и печатает, что получилось.

```python
feats = ST.features_of(E)
R = ST.model_frame(E, feats)
train23, test23 = ST.split_people(R)
print("признаки:", feats)
print(f"строк для моделей: {len(R):,} (train {len(train23):,}, test {len(test23):,}); "
      f"событий в train: {int(train23['event'].sum()):,}")
R[feats].describe().T[["mean", "std", "min", "max"]].round(3)
```

Вход — таблица эпизодов `E` из [[10_ячейка_таблица_эпизодов]] (одна строка = одно заключение: `T`, `event`, `at_risk`, признаки).

---

## 1. `feats = ST.features_of(E)`: какие признаки есть

```python
def features_of(E):
    return [f for f in OBJECT_FEATURES + EVENT_FEATURES if f in E.columns and E[f].notna().any()]
```
Берёт заранее заданный список из 10 признаков и оставляет те, которые реально есть в таблице и не пустые целиком. Функция общая для всех кейсов: например, у данных Даши нет `old_case`, и там он просто выпадет. В exp3 остаются все 10.

**Признаки объекта** (свойства человека, не меняются от заключения к заключению):

| признак | что это |
|---|---|
| `age10` | возраст / 10 (на дату оценки COMPAS), чтобы коэффициент читался «на 10 лет» |
| `male` | 1 — мужчина |
| `race_afam` | 1 — афроамериканец |
| `race_other` | 1 — другая раса (не белый и не афроамериканец); база сравнения — белые |
| `score` | балл риска COMPAS (decile_score, 1–10) |

**Признаки события** (свойства текущего заключения):

| признак | что это |
|---|---|
| `felony` | 1 — самое тяжёлое обвинение в заключении — фелония |
| `n_charges` | число обвинений (обрезано до 10) |
| `log_dur` | log(1 + дней в заключении) |
| `prior_eps` | сколько заключений было раньше (обрезано до 5) |
| `old_case` | 1 — в заключении есть обвинение по старому делу |

Текущее **состояние** (`state`) в этот список не входит. Его модели получают отдельно, потому что это категория, а не число: в Кохе — как страты или набор 0/1-колонок, в деревьях — как закодированный признак.

Важно, что все признаки известны **на момент выхода** из текущего заключения. В них нет ничего из будущего, то есть нет утечки, которая была у Даши (там признаки брались из следующей строки, и время с последнего ареста фактически содержало ответ).

## 2. `R = ST.model_frame(E, feats)`: строки, пригодные для моделей

```python
def model_frame(E, feats):
    R = E[E["at_risk"]].dropna(subset=feats).copy()
    R["T"] = _pos(R["T"])
    return R
```
1. `E[E["at_risk"]]` убирает 635 заключений, которые на конец наблюдения ещё не закончились: человек не выходил на свободу, и время для него ещё не пошло (подробно в [[11_каплан_мейер_шаг_2_3]]).
2. `.dropna(subset=feats)` убирает строки, где пуст хотя бы один признак. В exp3 это строки без балла COMPAS. Модели Кокса и деревья не умеют работать с пропусками, поэтому такие строки нужно либо выбросить, либо заполнить. Их всего 14, поэтому их выбросили.
3. `.copy()` создаёт отдельную таблицу, чтобы изменения не попадали в `E`.
4. `_pos(T)` заменяет время меньше 0.5 дня на 0.5: `max(T, 0.5)`. У 107 переходов T = 0 (сел снова в день выхода). Параметрическим моделям и части методов нужно строго положительное время, а полдня ничего не меняет по смыслу.

Итог: 21 716 − 635 − 14 = **21 067 строк**.

## 3. `train23, test23 = ST.split_people(R)`: train и test

```python
def split_people(E, seed=SEED, test_share=0.2):
    rng = np.random.default_rng(seed)
    ids = E["id"].unique()
    test_ids = set(rng.choice(ids, size=int(test_share * len(ids)), replace=False))
    is_test = E["id"].isin(test_ids)
    return E[~is_test].copy(), E[is_test].copy()
```
Деление **по людям**, 80/20, seed 42: все заключения одного человека попадают в одну часть. Иначе модель видела бы на обучении одного и того же человека (его балл, возраст, привычный тип обвинений) и на тесте узнавала бы его, а C-index получился бы завышенным. Смысл тот же, что на этапе 1 ([[03_train_test]]).

Уточнение. Правило то же, что на этапе 1, но **люди в test не те же самые**. Генератор с тем же seed выбирает 20% из другого списка: здесь номера людей из `R` в своём порядке, а на этапе 1 — из журнала PM4Py, где номера — строки. Для оценки моделей это неважно: внутри этапа 3 все модели сравниваются на одном и том же `test23`. Но говорить «тот же test, что на этапе 1» нельзя.

## 4. Печать

```python
print("признаки:", feats)
print(f"строк для моделей: {len(R):,} (train {len(train23):,}, test {len(test23):,}); "
      f"событий в train: {int(train23['event'].sum()):,}")
```
`:,` в f-строке ставит разделитель тысяч. В твоём запуске:

```
признаки: ['age10', 'male', 'race_afam', 'race_other', 'score', 'felony', 'n_charges', 'log_dur', 'prior_eps', 'old_case']
строк для моделей: 21,067 (train 16,763, test 4,304); событий в train: 8,820
```

- Строк в test 4 304 (20.4%), а не ровно 20%: делили людей, а у людей разное число заключений.
- **Событий в train 8 820** из 16 763 строк, то есть у 53% заключений наблюдался следующий переход, а 47% цензурированы. Для моделей выживаемости важно именно число событий, а не строк: на нём оцениваются коэффициенты. 8 820 событий на 10 признаков — это очень много, переобучения коэффициентов можно не бояться. Обычное правило — хотя бы 10–20 событий на признак.

## 5. `R[feats].describe()`: краткая статистика признаков

`.describe()` считает статистики каждой колонки, `.T` переворачивает таблицу (признаки в строки), из неё берутся среднее, стандартное отклонение, минимум и максимум.

| признак | среднее | std | min | max | как читать |
|---|---|---|---|---|---|
| age10 | 3.37 | 1.14 | 1.8 | 9.6 | средний возраст 34 года, от 18 до 96 |
| male | 0.82 | | 0 | 1 | 82% заключений — мужчины |
| race_afam | 0.54 | | 0 | 1 | 54% — афроамериканцы |
| race_other | 0.13 | | 0 | 1 | 13% — другие расы; белых, значит, около 33% |
| score | 5.23 | 2.94 | 1 | 10 | балл COMPAS в среднем посередине шкалы, разброс по всей шкале |
| felony | 0.64 | | 0 | 1 | в 64% заключений есть фелония |
| n_charges | 2.75 | 2.15 | 1 | 10 | в среднем почти 3 обвинения |
| log_dur | 1.99 | 1.67 | 0 | 7.09 | e^1.99 − 1 ≈ 6 дней — «типичная» длительность (геометрическое среднее); максимум e^7.09 ≈ 1200 дней |
| prior_eps | 1.02 | 1.36 | 0 | 5 | в среднем одно прошлое заключение |
| old_case | 0.26 | | 0 | 1 | в 26% заключений есть старое дело |

Для 0/1-признаков среднее = доля единиц. Стандартное отклонение у них ничего нового не добавляет, поэтому в пояснениях пропущено.

Эту таблицу полезно вставить в диплом как «описательную статистику выборки для моделей этапа 3».

Дальше в ноутбуке на `train23` обучаются модели, а на `test23` считается C-index (3.1–3.4).
