## 2. Настройка окружения

```python
warnings.filterwarnings("ignore")
```
Отключает все предупреждения. PM4Py и pandas выдают много сообщений вроде «эта функция устареет», и они засоряют вывод. На результат это не влияет.

```python
os.environ["PM4PY_SHOW_PROGRESS_BAR"] = "False"
```
Выключает полоски прогресса PM4Py. Без этой строки каждый replay печатает тысячи строк прогресса, и ноутбук раздувается до десятков мегабайт.

```python
for gv in [Path(r"D:\Graphviz\bin")]:
    if gv.exists() and str(gv) not in os.environ["PATH"]:
        os.environ["PATH"] = str(gv) + os.pathsep + os.environ["PATH"]
```
PM4Py рисует графы программой **Graphviz** (`dot.exe`). Python ищет программы в списке папок из переменной `PATH`.
- `r"D:\Graphviz\bin"`: буква `r` означает «сырую» строку, чтобы `\G` и `\b` не превратились в спецсимволы;
- `gv.exists()`: папка существует (на твоём ноутбуке да, в облаке нет, тогда строка просто ничего не делает);
- `str(gv) not in os.environ["PATH"]`: папку ещё не добавили, чтобы при повторном запуске не дублировать;
- `os.pathsep`: разделитель папок в PATH (`;` на Windows, `:` на Linux). Папку Graphviz ставим **в начало** списка.

Цикл `for` по списку из одного элемента сделан для того, чтобы при необходимости можно было дописать ещё варианты путей.

```python
import pm4py
import x2_common as X
```
Импорт PM4Py стоит **после** настройки PATH и прогресс-бара, чтобы библиотека сразу подхватила эти настройки.
`x2_common.py` лежит рядом с ноутбуком. Это наш общий модуль для всех экспериментов ×2: `X.build(...)` (сборка журнала), `X.split_people(...)` (train/test), `X.evaluate(...)` (fitness/precision). `as X` — короткое имя.

`.parent` означает «на уровень выше». Два раза вверх: `x2_exp3_...` → `stage1` → `jupyter lab`. В репозитории GitHub это корень репозитория.

```python
CANDIDATES = [ROOT / "stage0 - data" / "out" / "compas_custody_charges.csv",
```

Два места, где может лежать входная таблица:

```python
DATA = next((p for p in CANDIDATES if p.exists()), CANDIDATES[0])
```

Берём первый существующий путь из списка. `(p for p in ... if p.exists())` — генератор, который перебирает только существующие пути, а `next(...)` берёт первый. Если не существует ни один, вернётся `CANDIDATES[0]`. Тогда `print` ниже покажет `False`, и станет понятно, что файл не найден.

Папки для результатов: `out` для таблиц, `out\figures` для картинок.
`mkdir(parents=True)` создаёт и промежуточные папки (`out`, если её нет), а `exist_ok=True` не выдаёт ошибку, если папка уже есть.

## 4. Параметры эксперимента

```python
EXP = "x2_exp3_one_event_merge"
```
Имя эксперимента. Используется в названиях файлов, например `event_log_x2_exp3_one_event_merge.csv`.

```python
BUILD = {'one_event': True}
```
Параметры сборки журнала, передаются в `X.build(...)`. `one_event=True` означает **одно событие на заключение**: из всех категорий заключения остаётся самая тяжёлая (Justice только если она одна). В основном варианте ×2 было по событию на каждую категорию, и цепочки внутри одного заключения сильно снижали precision. Это главная идея exp1 и exp3.

```python
MERGE_RARE = True
MIN_EVENTS = 300
```
Второе изменение exp3: редкие состояния вида `OldCase: X`, у которых **меньше 300 событий**, сливаются в одно общее `OldCase: Other`. Меньше редких состояний означает меньше случайных дуг и более точную модель.

```python
MODELS = ['HM_0.5', 'HM_0.9', 'HM_0.95', 'IM_0.2', 'IM_0.5']
```
Какие модели строить и сравнивать:
- `HM_0.5 / 0.9 / 0.95` — Heuristics Miner с порогом зависимости 0.5, 0.9, 0.95;
- `IM_0.2 / 0.5` — Inductive Miner с порогом шума 0.2 и 0.5.

```python
EVAL_CASES = 2000
```
Сколько людей брать из train и из test для расчёта fitness и precision (см. мой прошлый ответ про деление на train и test).

```python
RUN_ILP = False
```
ILP Miner — ещё один алгоритм (через целочисленное линейное программирование). На 300 людях он не закончил работу за 6 минут, поэтому по умолчанию выключен. Поставишь `True`, если захочешь запустить его на ночь.

```python
ALIGN_CASES = 2000
```
Precision через **выравнивания** (точный, но медленный способ) считается только для HM 0.9, на 2000 людях из test. `0` означает «не считать». В комментарии объяснено, почему 2000, а не меньше: precision смотрит на префиксы трасс, и на маленькой выборке часть реально бывающих переходов просто не встречается, поэтому модель кажется «разрешающей лишнее» и precision занижается.

```python
print("pm4py", pm4py.__version__, "| вход:", DATA, DATA.exists())
```

Контрольная печать: версия PM4Py (у тебя 2.7.23.9), путь к входному файлу и `True/False`, найден ли он. Если там `False`, дальше ячейки упадут: значит, таблица stage0 не на месте.

## 5. Функция `show`: показать большую картинку

```python
def show(path, max_px=1400):
```
Своя функция для показа PNG. `max_px=1400` — значение по умолчанию: наибольшая сторона картинки в пикселях.

```python
    from io import BytesIO
    from PIL import Image as PILImage
```
- `BytesIO` — «файл в памяти», чтобы не писать временный файл на диск;
- `PIL` (библиотека Pillow) работает с картинками. Переименована в `PILImage`, потому что имя `Image` уже занято объектом из IPython.

```python
    PILImage.MAX_IMAGE_PIXELS = None
```
Pillow по умолчанию отказывается открывать очень большие картинки (защита от «бомб»). Наши графы бывают огромными (сеть Петри больше 5 МБ), поэтому ограничение снимаем.

```python
    im = PILImage.open(path)
    im.thumbnail((max_px, max_px))
```
Открываем картинку и уменьшаем, сохраняя пропорции, чтобы наибольшая сторона была не больше 1400 px. Сам файл на диске не меняется, в нём остаётся полное разрешение.

```python
    buf = BytesIO()
    im.convert("RGB").save(buf, format="JPEG", quality=80)
```
Пересохраняем в JPEG с качеством 80% в память. `convert("RGB")` нужен потому, что PNG бывает с прозрачностью, а JPEG её не поддерживает. JPEG весит в разы меньше PNG, и ноутбук остаётся лёгким.

```python
    display(Image(data=buf.getvalue(), format="jpeg"))
```
Показываем уменьшенную картинку под ячейкой. `buf.getvalue()` — байты JPEG из памяти.

Зачем это всё: если вставить полный PNG графа в ноутбук, он весил бы десятки мегабайт и медленно открывался. Так в ноутбуке лежит лёгкое превью, а полная картинка остаётся в `out\figures`.
