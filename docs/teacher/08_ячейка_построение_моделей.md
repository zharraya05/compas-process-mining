# Ячейка «деление и построение моделей» (ноутбуки x2_exp*) построчно

Ячейка делит людей на train и test, выбирает людей для оценки и строит модели из списка `MODELS`. Названия моделей задаются строкой, и функция `discover` по этой строке понимает, какой алгоритм и с какими параметрами запускать.

---

## 1. Деление и выборки для оценки

```python
train, test = X.split_people(log)
```
`log` — журнал событий, собранный `X.build(...)`. `split_people` из `x2_common.py` случайно (seed 42) отправляет 20% людей в `test`, остальных в `train`. Все события одного человека попадают в одну часть. Подробнее в [[03_train_test]].

```python
train_s, test_s = X.sample_cases(train, EVAL_CASES), X.sample_cases(test, EVAL_CASES)
```
Из каждой части берутся первые `EVAL_CASES` = 2000 человек (по номеру, отсортированному как текст). На этих выборках потом считаются fitness и precision. Модели строятся на **всём** `train`, а не на `train_s`.

## 2. `frequent_train()`: только частые трассы

```python
def frequent_train():
    # люди из train, чья трасса (последовательность событий) встречается хотя бы у двух человек
```
Функция возвращает часть `train`, в которой остались только люди с **неуникальной** трассой. Используется в моделях с суффиксом `_freq` (эксперимент exp4).

```python
    seq = train.groupby("case:concept:name")["concept:name"].agg(tuple)
```
Для каждого человека собираем его трассу в кортеж, например `('Drug', 'Traffic', 'OldCase: Drug')`. Кортеж (`tuple`), а не список, потому что кортеж можно сравнивать и считать как одно значение. Порядок событий берётся из порядка строк журнала, а `build` уже отсортировал их по времени.
Результат `seq` — Series: индекс = человек, значение = его трасса.

```python
    n = seq.map(seq.value_counts())
```
`seq.value_counts()` считает, сколько людей имеют каждую трассу (это **варианты** и их частоты). `seq.map(...)` подставляет каждому человеку частоту его трассы. Итог `n`: индекс = человек, значение = сколько людей идут тем же путём.

```python
    return train[train["case:concept:name"].isin(n[n >= 2].index)]
```
Оставляем события людей, у которых трасса встречается хотя бы у двоих (`n >= 2`).

Зачем это нужно. Уникальные трассы — самые «шумные»: редкие комбинации переходов, которые модель потом пытается разрешить, и из-за этого precision падает. Если строить модель только на повторяющихся путях, она получается строже. В exp4 так вышло: HM 0.9 на частых трассах дал precision **0.880**, но fitness упала до **0.940**, потому что модель хуже описывает людей с редкими путями. Проверка при этом идёт на обычных `train_s` и `test_s`, со всеми людьми.

## 3. `discover(name)`: имя модели → алгоритм

```python
def discover(name):
```
Принимает строку вроде `"HM_0.9"`, `"HM_0.9_freq"`, `"HM_0.9_min30"`, `"IM_0.2"`, `"ILP"` и возвращает сеть Петри в виде тройки `(net, im, fm)`: сеть, начальная разметка, конечная разметка.

### Heuristics Miner
```python
    if name.startswith("HM_"):
        parts = name.split("_")
```
`"HM_0.9_min30".split("_")` даёт `['HM', '0.9', 'min30']`. Второй элемент — порог.

```python
        lg = frequent_train() if name.endswith("_freq") else train
```
На каком журнале строить: только частые трассы (если имя кончается на `_freq`) или весь `train`.

```python
        kw = dict(dependency_threshold=float(parts[1]))
```
Параметры алгоритма собираются в словарь. `float("0.9")` превращает текст в число. Про порог dependency см. [[05_пороги_HM]] и [[06_слабые_и_шумовые_дуги_HM]].

```python
        if "min30" in name:
            kw["min_dfg_occurrences"] = 30
```
Вариант `min30`: дуга DFG учитывается, только если встретилась не меньше 30 раз (по умолчанию 1). Редкие дуги отбрасываются до всех остальных правил. В exp4 это дало precision 0.660 при fitness 0.971.

```python
        return pm4py.discover_petri_net_heuristics(lg, **kw)
```
Запуск Heuristics Miner. `**kw` раскрывает словарь в именованные аргументы, то есть получается вызов `discover_petri_net_heuristics(lg, dependency_threshold=0.9, min_dfg_occurrences=30)`. Функция сразу переводит heuristics net в сеть Петри.

### Inductive Miner
```python
    if name.startswith("IM_"):
        lg = frequent_train() if name.endswith("_freq") else train
        return pm4py.discover_petri_net_inductive(lg, noise_threshold=float(name.split("_")[1]))
```
То же самое для Inductive Miner: выбор журнала и порог шума из имени (`"IM_0.2"` → 0.2). `noise_threshold` — какую долю редкого поведения IM разрешено проигнорировать при разрезании журнала.

### ILP Miner
```python
    if name == "ILP":
        return pm4py.discover_petri_net_ilp(train)
```
ILP Miner строит сеть Петри, решая задачу целочисленного линейного программирования: ищет позиции, которые не запрещают ни одной трассы журнала. Даёт точные модели, но работает очень медленно. На 300 людях не закончил за 6 минут, поэтому выключен (`RUN_ILP = False`).

```python
    raise ValueError(name)
```
Если имя не подошло ни под одно правило (опечатка в `MODELS`), функция выдаёт ошибку с этим именем, а не молча возвращает пустоту.

## 4. Цикл построения моделей

```python
models, times = {}, {}
```
Два пустых словаря: `models[имя] = (net, im, fm)` и `times[имя] = секунды построения`.

```python
for name in MODELS:
    if name == "ILP" and not RUN_ILP:
        continue
```
Перебираем модели из списка в первой ячейке. ILP пропускается (`continue` — перейти к следующей), если он выключен.

```python
    t0 = time.time()
    models[name] = discover(name)
    times[name] = round(time.time() - t0)
```
Засекаем время, строим модель, записываем, сколько секунд это заняло (колонка `discover_sec` в таблице качества). На exp3 все модели строятся быстрее секунды, поэтому там стоят нули.

Дальше в ноутбуке словарь `models` передаётся в `X.evaluate(models, train_s, test_s, ...)`, который считает метрики (см. [[07_x2_common_построчно]]).

## Какие модели в каком эксперименте
- exp1–exp3: `HM_0.5`, `HM_0.9`, `HM_0.95`, `IM_0.2`, `IM_0.5`. Ветки `_freq`, `min30` и `ILP` в `discover` есть, но в этих ноутбуках не используются (код общий для всех экспериментов).
- exp4 (настройки майнеров, на основном журнале ×2 без `one_event`): `HM_0.9`, `HM_0.95`, `HM_0.99`, `HM_0.9_min30`, `HM_0.9_and0.95`, `IM_0.2`, `IM_0.3`, `IM_0.5`, `HM_0.9_freq`, `IM_0.2_freq`, `ILP`. В ноутбуке exp4 `discover` дополнительно понимает `and0.95` (порог AND-меры 0.95).

Результаты exp4 (test):

| модель | fitness | precision |
|---|---|---|
| HM_0.9 (база) | 0.982 | 0.543 |
| HM_0.99 | 0.970 | 0.594 |
| HM_0.9_min30 | 0.971 | 0.660 |
| HM_0.9_and0.95 | 0.983 | 0.544 |
| HM_0.9_freq | 0.940 | 0.880 |
| IM_0.2_freq | 0.959 | 0.552 |

Вывод: настройки майнера (min30, freq) поднимают precision ценой fitness. Сильнее всего precision выросла от изменения самого журнала (exp3: одно событие на заключение и слияние редких состояний, precision 0.826 при fitness 0.985).
