# Подготовка данных COMPAS для графа переходов: отчёт к встрече

9 октября 2026. Диплом: граф переходов между повторяющимися событиями (process mining) + модель следующего события как конкурирующих рисков с цензурированием.

## 0. Коротко

- Входные данные теперь строятся **напрямую из ProPublica `compas.db`** скриптом `build_from_compas_db.py`, без промежуточного CSV Даши.
- Объект = человек, `id` = `casearrest.person_id` (= `people.id`). Имя больше не ключ: у Даши 119–133 имени склеивали разных людей.
- **Одна строка = одно обвинение внутри одного заключения.** Все обвинения заключения сохранены (у Даши было одно индексное обвинение COMPAS на человека, скопированное во все строки).
- Итог: **65 363 строки, 22 552 заключения, 10 580 человек**, период 2013-01-01 — 2016-04-19.
- Для графа таблица сворачивается в эпизоды: jail → prison в день освобождения склеивается (21 716 эпизодов), обвинения группируются в 15 типов, повторный арест по уже известному делу помечается состоянием **OldCase** (19% эпизодов).
- Терминального состояния нет: последнее заключение каждого человека цензурировано концом наблюдения 2016-04-19.

## 2. Как собирается таблица (`build_from_compas_db.py`)

Запуск: `python build_from_compas_db.py D:\diploma\compas.db <папка вывода>`; база открывается только на чтение.

1. **Люди.** Берутся все `person_id` из `casearrest`. `age`, `sex`, `race` — из `people` по `id`.
2. **Заключения.** Объединяются `jailhistory` и `prisonhistory` (`custody_source` = jail / prison). Берутся заключения с входом не раньше 2013-01-01: `jailhistory` в базе начинается с этой даты, а ранние сроки prison дали бы ложные многолетние промежутки. Сортировка по `id`, `in_custody`; `custody_num` = номер заключения у человека.
3. **Обвинения к заключению** (по приоритету, `charge_source`):
   - `arrest` — все дела из `casearrest`, арестованные в ±1 день от `in_custody`; берутся все обвинения этих дел из `charge` (20 368 заключений);
   - `offense` — дела с датой преступления за 7 дней до входа (71);
   - `prior_case` — последнее дело за 365 дней до входа: заключение по приговору или нарушению условий (1 335);
   - `none` — обвинений не найдено, строка одна, обвинение пустое (778).
4. **Разворот в строки.** Каждое обвинение — отдельная строка; поля заключения повторяются. `charge_num` — номер обвинения в заключении, `n_charges` — их число.
5. **Категория** `charge_category` — 9 групп по ключевым словам (`crime_categories.py`, наша группировка, у Даши её не было). Для графа она уточняется до 15 типов (раздел 5).
6. **Производные столбцы** считаются по `id` формулами Даши (раздел 3).
7. Запись `compas_custody_charges.csv` и `.xlsx`.

Проверено: если арест был в ±1 день от входа, в таблицу попадают все обвинения всех дел этого ареста (совпадение с `charge` в 100% из 20 368 заключений). 54 дела из 26 740 не имеют записей в `charge`, по ним обвинения теряются.

## 3. Структура итоговой таблицы `compas_custody_charges`

**Уровни:** человек (`id`) → заключение (`id`, `custody_num`) → обвинение (`charge_num`). Ключ строки: (`id`, `custody_num`, `charge_num`). Поля человека одинаковы во всех его строках, поля заключения одинаковы во всех строках заключения.

Колонка «момент» показывает, известно ли значение на момент входа в заключение (**прошлое** — можно использовать как признак) или это **будущее** (цель модели, в признаки нельзя: именно такая ошибка дала утечку у Даши).

| # | Столбец | Тип | Уровень | Источник / формула | Пропуски | Момент |
|---|---|---|---|---|---|---|
| 1 | `id` | int | человек | `casearrest.person_id` (= `people.id`) | 0 | — |
| 2 | `age` | int | человек | `people.age` (возраст на дату COMPAS-оценки), 18–96, медиана 32 | 0 | прошлое |
| 3 | `sex` | str | человек | `people.sex`: Male 8 414, Female 2 166 человек | 0 | прошлое |

| 18 | `all_future_arrest_times` | список | заключение | дни от текущего `in_custody` до каждого будущего, например `[328]` | у последних | **будущее** |
| 19 | `all_future_events` | список | заключение | `[1]` × число будущих заключений + `[0]`, например `[1, 0]` | 0 | **будущее** |

## 5. Уровень эпизода для графа (`stage1_compasdb/stage1_compasdb.py`)

Из таблицы обвинений строится журнал событий:

1. **Склейка jail → prison.** Prison, начатый в день выхода из предыдущего заключения, — это приговор по тому же делу; он приклеивается к предыдущему (829), плюс 7 заключений с одной датой входа. 22 552 заключения → **21 716 эпизодов**.
2. **Старые дела → OldCase.** Обвинение старое, если его `case_number` уже был у человека в прошлом эпизоде. Эпизод только из старых обвинений получает состояние **OldCase** (4 066 эпизодов, 37% повторных); в смешанных эпизодах (1 677) старые обвинения отбрасываются. Всего старых обвинений 18 875 из 65 363.
3. **15 типов преступлений.** 9 групп плюс Other разбит на ResistPolice, PublicOrder, Tampering, Justice, Conspiracy, Minors, около 800 ошибочных Other перенесены в основные типы, 136 формулировок ПДД — в Traffic. Состояния: Traffic, Property, Drug, Violent, Fraud, ResistPolice, Sex, PublicOrder, Weapon, Tampering, Justice, Conspiracy, Minors, Other, Unknown + OldCase.
4. **Состояние эпизода = множество типов** его новых обвинений; несколько типов = развилка (27% эпизодов). Justice ставится отдельным шагом после остальных типов (101 эпизод).
5. **Журнал PM4Py:** `case:concept:name` = `id`, `concept:name` = тип, `time:timestamp` = `in_custody`; по событию на тип, порядок внутри эпизода случайный (seed 42).
6. **Цензура:** терминала нет, последний эпизод каждого из 10 580 человек цензурирован 2016-04-19.

Итог журнала: 21 716 эпизодов, 5 230 человек с повторами, **11 237 переходов**, 29 371 событие по типам. Эпизодов на человека: 1 — 5 350, 2 — 2 421, 3 — 1 323, 4 — 698, далее хвост.

Варианты для сравнения: «все обвинения новые» (`results/`), без склейки (`results_nomerge/`), эпизоды OldCase удалены из цепочки (`stage1_compasdb_no_oldcase/`), склейка повторов в ±7 дней (`results_glue_*`, почти ничего не меняет).

## 7. Особенности данных

- 778 заключений без обвинения (Unknown, 3%).
- 661 заключение с `out_custody = 2020-01-01` (ещё в заключении на момент выгрузки).
- 863 заключения с `time_since_last_arrest = 0` (переход jail → prison) и 79 с отрицательным значением (пересекающиеся записи, 60 jail и 19 prison); одно заключение с отрицательной длительностью.
- 738 человек из таблицы Даши нет в `casearrest`; 383 человека из `casearrest` без заключений с 2013 года.
- В `charge` нет дат добавления обвинений и нет отметок о нарушении условий (VOP), неявке (FTA), поэтому OldCase — лучшее приближение «ареста по ордеру».
- Обвинения одного заключения имеют одну дату, порядок внутри неизвестен — отсюда развилки.
- `compas-scores-raw.csv` для задачи не нужен: в нём только оценки COMPAS, без арестов и заключений.
