# Шаг 3.4: случайный лес выживаемости и важность признаков

Продолжение [[17_дерево_выживаемости_3_3]]. Одно дерево читается легко, но неточно и неустойчиво. Случайный лес строит много разных деревьев и усредняет их. Он точнее, но его уже нельзя нарисовать, поэтому для объяснения считают **важность признаков**.

## 1. Что такое Random Survival Forest (RSF)

Это то же дерево выживаемости из 3.3, повторённое много раз со случайностью:
1. **Бутстрэп.** Каждое дерево обучается на своей случайной выборке из train того же размера, но с повторами: одни заключения попадают в неё 2–3 раза, другие ни разу.
2. **Случайные признаки.** В каждом узле дерево выбирает разбиение не из всех признаков, а из случайного подмножества. `max_features="sqrt"`: из ~30 колонок (10 признаков + по колонке на каждое состояние) рассматривается √30 ≈ 5. Это делает деревья непохожими друг на друга.
3. **Глубокие деревья.** Ограничения на глубину нет, только `min_samples_leaf=50`: лист не меньше 50 заключений. Каждое отдельное дерево переобучено, но их ошибки разные и при усреднении гасятся.
4. **Предсказание.** Для нового человека каждое из 100 деревьев (`n_estimators=100`) даёт кривую накопленного риска его листа, лес усредняет 100 кривых. Риск для C-index — сумма усреднённого накопленного риска.

Чем лес хорош по сравнению с Коксом:
- не предполагает **пропорциональность** рисков (эффект может меняться со временем);
- сам находит **взаимодействия** (как «длительность важна только при балле 9–10» в дереве) и **нелинейности** (например, если важен только балл ≥ 8, а не каждый балл одинаково).

Если лес заметно точнее Кокса, значит, в данных есть то, что Кокс пропускает. Если примерно так же — линейная модель Кокса описывает данные достаточно хорошо, и её HR можно доверять как сводке.

## 2. Код построчно

```python
if RUN_RSF:
    rsf_c, rsf_imp, rsf_sec = ST.random_forest(train23, test23, feats)
```
`RUN_RSF` — флаг в начале ноутбука: лес самый долгий шаг, его можно выключить. У тебя он занял 7 секунд.

Внутри `random_forest`:
```python
X_tr, y_tr = _xy(train, feats, states)        # те же X и y, что для дерева
rsf = RandomSurvivalForest(n_estimators=100, min_samples_leaf=50, max_features="sqrt",
                           n_jobs=-1, random_state=SEED, low_memory=True).fit(X_tr.values, y_tr)
base = rsf.score(X_te.values, y_te)           # C-index на test
```
- `n_jobs=-1` — строить деревья на всех ядрах процессора параллельно;
- `random_state=SEED` (42) — воспроизводимость: те же деревья при повторном запуске;
- `low_memory=True` — не хранить в листьях полные кривые, только то, что нужно для риска. Экономит память, но `predict_survival_function` с этим флагом не работает. Нам нужен только C-index.

### Важность перестановкой (permutation importance)
```python
groups = {f: [f] for f in feats}
groups["state"] = [c for c in X_te.columns if c.startswith("st_")]
for g, cols in groups.items():
    for _ in range(repeats):                   # 3 повтора
        Xp = X_te.copy()
        perm = rng.permutation(len(Xp))
        Xp[cols] = X_te[cols].values[perm]     # перемешать значения признака между людьми test
        drops.append(base - rsf.score(Xp.values, y_te))
    imp[g] = np.mean(drops)
```
Идея: **если признак важен, то после его перемешивания модель станет хуже**.
1. Берём test и перемешиваем один столбец: каждому человеку достаётся балл (или возраст…) случайного другого человека. Остальные признаки не трогаем. Связь этого признака с результатом разрушена, а его распределение то же.
2. Считаем C-index леса на испорченных данных.
3. Важность = **насколько упал C-index**. Повторяем 3 раза с разными перестановками и усредняем, чтобы уменьшить случайность.

Лес при этом **не переобучается**: проверяется, насколько уже обученная модель опирается на признак.

**Состояние перемешивается целиком**: все колонки `st_*` переставляются одной и той же перестановкой. Каждый человек получает полный набор 0/1 другого человека, то есть ровно одно состояние, но чужое. Если бы колонки перемешивались по отдельности, получились бы бессмысленные люди с двумя состояниями или без состояния, а важность состояния «размазалась» бы на два десятка мелких кусков.

## 3. Результат

**C-index леса на test 0.678** (Кокс «состояние + признаки» 0.675, дерево 0.653).

| признак | падение C-index |
|---|---|
| балл COMPAS | **0.0933** |
| текущее состояние | 0.0146 |
| заключений до этого | 0.0142 |
| log длительности | 0.0050 |
| старое дело | 0.0034 |
| фелония | 0.0026 |
| мужчина | 0.0021 |
| число обвинений | 0.0009 |
| возраст | 0.0005 |
| др. раса | 0.0005 |
| афроамериканец | −0.0006 |

### Как читать
1. **Лес лишь на 0.003 лучше Кокса.** Значит, нелинейностей и взаимодействий, которые Кокс пропускает, почти нет, или они не помогают упорядочивать людей. Модель Кокса — адекватная сводка, её HR можно использовать как основной результат.
2. **Балл COMPAS важнее всего остального вместе взятого.** Без него C-index падает на 0.093: с 0.678 до ~0.585. Сумма всех остальных падений ≈ 0.044.
3. **Состояние и прошлые заключения — второе место** с одинаковой важностью (~0.014). Это совпадает с C-index Кокса: состояние добавляет к признакам немного.
4. **Возраст и раса почти не важны** (меньше 0.001) — как и в Коксе: при наличии балла они ничего не добавляют.
5. **Отрицательная важность** (афроамериканец −0.0006) значит, что после перемешивания C-index случайно стал чуть лучше. Это шум: признак не важен. Падения меньше ~0.002 вообще стоит считать неотличимыми от нуля.

### Важное ограничение метода
Если два признака связаны, перестановочная важность делит их вклад неочевидно. Балл COMPAS содержит в себе возраст и криминальную историю, поэтому перемешивание возраста почти ничего не меняет: лес «добирает» информацию о возрасте из балла. Низкая важность значит «модель **при наличии остальных признаков** почти не опирается на этот признак», а не «признак не связан с возвращением». Та же оговорка, что для Кокса в [[15_кокс_3_1_и_HR]] (без балла возраст значим).
