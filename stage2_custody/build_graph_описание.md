## 4. Привязка обвинений к заключениям

Заключения перебираются по человеку в порядке входа (код — константа `LINK_1711` в `build_graph.py`).

### 4.1. Арест в [вход − 1 день; вход]
- Арест человека в день входа или накануне. Берутся **все дела** таких арестов.
-  Обвинения, добавленные в дело позже (например, нарушение условий освобождения на свободе), попадут в следующее заключение по этому делу.
- Для каждого дела — было ли у человека **уже заключение по этому делу в окне** (вход с 01.01.2013; prison до 2013 не считается):

| Дела в [n − 1; n] | Причина | Состояние узла | Сборка 18.11 |
|---|---|---|---|
| только новые | `new_offense` | типы обвинений | 15 427 заключений |
| новые + старые (смешанное) | `new_offense` | типы обвинений **нового** дела; старое дело — полями | 1 496 |
| только старые | `rearrest_old_case` | **`OldCase`** (обвинения привязаны, но в состояние не входят) | 3 471 |

Поля старого дела (у `OldCase` и смешанных):
- `rearrest_case_ids` — номер(а) старого дела;
- `rearrest_prev_custody_ids` — прошлые заключения по нему (`дело: custody_id, …`);
- `rearrest_case_types` — типы обвинений старого дела (отдельное поле, не состояние);
- `rearrest_new_charges_n` — **новые обвинения по старому делу**: с датой позже входа в последнее прошлое заключение по делу и не позже входа в текущее (12 заключений);
- `rearrest_first_arrest_date`, `original_case_degrees` — первый арест по делу и степени его обвинений (справочно).

В `custody_charges.csv` у каждого обвинения: `old_case` — относится к старому делу этого заключения; `new_in_old_case` — новое обвинение по старому делу.

Пример (человек 9443, дело 15004707MM10A): арест 24.04.2015 → jail 25.04–26.04 (новое дело, обвинения от 24.04); 07.05 — обвинение `Viol Pretrial Release` по тому же делу, на свободе; арест 14.06 → jail 14.06–26.08 — **старое дело** (`OldCase`), обвинения 24.04 и 07.05 привязаны, 07.05 — новое обвинение по старому делу.

### 4.2. Переводы jail → prison и prison → jail
Непривязанное заключение — перевод, если заключение **другого источника** закончилось меньше чем за сутки до его входа и между ними у человека нет новых арестов и обвинений. Перевод наследует дело и причину **первого** заключения цепочки (jail → prison → jail — от первого jail) и склеивается с ним в один узел (`transfer_note`: «перевод … из custody_id=первое»). Найдено jail → prison 674, prison → jail 3; дело унаследовали 622, у 54 исходный jail сам не привязан.

### 4.3. jail внутри срока prison
Непривязанные jail, начавшиеся во время срока prison того же человека (включая сроки с заглушкой «ещё сидит» 2020-01-01), удаляются как технические записи: 29 (привязанные — 53 — остаются и на этапе 2 склеиваются со сроком в одно пребывание).

### 4.4. Остальное — Unknown
Заключение без ареста в [n − 1; n] и не перевод — не привязано. В том числе prison по приговору без ареста при входе.

## 8. Узлы графа (функции `этап 1/make_notebook.py`)

| Шаг | Правило |
|---|---|
| Узел | заключение; перевод склеен с первым заключением цепочки (склеено 670) |
| Конец наблюдения | 01.04.2016; у «ещё сидит» выход = конец наблюдения (`ongoing`) |
| Причина узла | первая непустая причина его записей, иначе «не привязано» |
| Состояние | множество 15 типов обвинений **без обвинений старого дела**; Unknown убирается, если есть известные типы |
| Узел без таких обвинений | `OldCase`, если причина `rearrest_old_case`; иначе `Unknown` |
| Тяжесть | `deg_rank` — самая тяжёлая степень **по всем обвинениям узла**, включая старое дело (1 F1 … 7 MO3, 8 прочее, 9 нет обвинений); `charge_class` — по обвинениям состояния |
| Старое дело | поля узла `rearrest_case_ids`, `rearrest_prev_custody_ids`, `rearrest_case_types`, `rearrest_new_charges_n`, флаг `old_case_flag` |
| Justice | при других типах — отдельным шагом после узла (96 шагов) |
| Цензура | последний шаг человека; `followup_days` — до конца наблюдения |


### Как читать узлы — пример (человек 96)

| Узел | Вход → выход | Источник | Причина | Состояние | Старое дело | Свобода до / после, дн. |
|---|---|---|---|---|---|---|
| 237 | 25.01.2013 → 13.02.2013 | jail | `new_offense` | Tampering+Violent | — | — / 51 |
| 238 | 05.04.2013 → 12.07.2013 | jail | `rearrest_old_case` | **OldCase** | 13001227CF10A (Tampering, Violent) | 51 / 43 |
| 239 | 25.08.2013 → 29.08.2014 | jail | `new_offense` | Property+ResistPolice+Violent | 13001227CF10A — смешанный узел | 43 / 43 |
| 240 | 12.10.2014 → 28.03.2016 | jail+prison | `rearrest_old_case` | **OldCase** | 13001227CF10A, 13011976CF10A | 43 / — (цензура) |

- 238: повторный арест по делу узла 237 → состояние `OldCase`; обвинения дела привязаны, но в состояние не входят — их типы в `rearrest_case_types`.
- 239: в тот же день новое дело и снова дело 13001227CF10A → состояние — типы нового дела, старое — полями.
- 240: jail 12.10.2014 (повторный арест по двум прошлым делам) и prison 23.04.2015 (перевод, разрыв меньше суток) склеены в один узел: вход из jail, выход из prison, `sources = jail+prison`, причина — от jail. Узел последний у человека → цензурирован.
- `deg_rank` = 2 (F2) у всех четырёх, в том числе у `OldCase`: тяжесть считается по всем обвинениям узла. `charge_class` у `OldCase` — `Other/NA`, потому что считается только по обвинениям состояния.

### Термины и счётчики

| Термин | Что это | Сборка 18.11 |
|---|---|---|
| узел (эпизод) | одно заключение или цепочка перевода; `ep_row` | 22 507 |
| шаг | строка журнала: узел + отдельный шаг Justice (если у узла есть Justice и другие типы, Justice идёт следующим шагом с тем же входом, разрыв 0) | 22 603 = 22 507 + 96 |
| переход | пара соседних шагов человека = шаги − люди | 11 579 |
| людей с повторами | больше одного шага | 5 363 |
| узлов с несколькими типами | состояние из 2+ типов (развилка в графе) | 25% |
| ещё сидят | выход после 01.04.2016 или заглушка 2020-01-01 → выход = 01.04.2016, `ongoing` | 731 |
| отрицательный разрыв | следующий узел начался до выхода из предыдущего (`gap_prev < 0`) | 251 |

**Отрицательные разрывы.** Узлы не пересекаются только для переводов (они склеены). Привязанный jail внутри срока prison не удаляется (п. 4.3) и остаётся отдельным узлом. Пример (человек 11): prison 06.08.2014 → «ещё сидит», не привязан (`Unknown`); внутри него jail 07.04.2015 → 20.04.2015 по старому делу (`OldCase`), `gap_prev` = −360. На этапе 2 такие узлы склеиваются в одно пребывание (`MERGE_GAP_DAYS`), выхода на свободу между ними нет.

**Поля узла** (`event_table.csv`): `id` — человек; `in_custody` / `out_custody`; `custodies` — сколько записей склеено; `sources` — jail / prison / jail+prison; `reason`; `combo` / `types` — состояние; `n_types`; `charge_class`, `deg_rank`; `dur`, `dur_class` — длительность и её класс (≤1 / 2–30 / 31–180 / >180 дней); `age`, `age_group`, `sex`, `race`, `decile_score` — из `people`; `step`, `event_idx`, `n_events` — порядок; `gap_prev`, `gap_next` — дни на свободе до и после; `prev_combo` — состояние предыдущего шага; `censored`, `followup_days`; `start_state`, `in_custody_true` — начальные prison (только `event_table_stage2.csv`); поля старого дела и `old_case_flag`.

**Итог графа:** 22 507 узлов у 11 024 человек, 22 603 шага, 11 579 переходов; `OldCase` 3 470, `Unknown` 2 267; узлов со старым делом 4 963 (смешанных 1 493), с новыми обвинениями по старому делу 12; узлов с несколькими типами 25%; ещё сидят 731.
