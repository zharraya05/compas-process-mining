# Ячейка «оценка качества моделей» (ноутбук exp3) построчно

Идёт сразу после построения моделей ([[08_ячейка_построение_моделей]]). Считает fitness и precision каждой модели на train и test, для HM 0.9 дополнительно считает precision через выравнивания, сохраняет таблицу `out/model_quality.csv` и показывает строки test.

```python
quality = X.evaluate(models, train_s, test_s)
quality["discover_sec"] = quality["model"].map(times)
if ALIGN_CASES and "HM_0.9" in models:
    t0 = time.time()
    pa = pm4py.precision_alignments(X.sample_cases(test, ALIGN_CASES), *models["HM_0.9"])
    quality.loc[(quality["model"] == "HM_0.9") & (quality["split"] == "test"), "precision_align"] = round(pa, 4)

quality.to_csv(OUT / "model_quality.csv", index=False)
quality[quality["split"] == "test"]
```

## Построчно

```python
quality = X.evaluate(models, train_s, test_s)
```
`evaluate` из `x2_common.py` ([[07_x2_common_построчно]]) проходит по всем моделям. Для каждой модели и для каждой выборки (train_s, test_s, по 2000 человек) он:
- прогоняет трассы фишками по сети Петри (token-based replay) и получает fitness и долю полностью подходящих трасс;
- считает precision тем же replay;
- считает F1 и размер сети (позиции, переходы, немые переходы).

Результат — таблица `quality`: по две строки на модель (train и test). Каждая строка ещё и печатается в ходе работы, поэтому под ячейкой видны словари вида `{'model': 'HM_0.5', 'split': 'train', ...}`.

Аргумент `align_cases` здесь не передан (по умолчанию 0), поэтому внутри `evaluate` выравнивания не считаются. Их считают ниже, отдельно и только для одной модели.

```python
quality["discover_sec"] = quality["model"].map(times)
```
Добавляется колонка: сколько секунд строилась модель. `times` — словарь `{имя модели: секунды}` из предыдущей ячейки. `.map(times)` подставляет каждой строке значение по имени модели. На exp3 там везде 0: модели строятся меньше чем за секунду.

```python
if ALIGN_CASES and "HM_0.9" in models:
```
Выравнивания считаются, только если `ALIGN_CASES` не равен 0 (в первой ячейке стоит 2000) **и** модель HM 0.9 есть в списке. Если её закомментировать в `MODELS`, блок просто пропустится, а не упадёт.

```python
    t0 = time.time()
```
Засекаем время, чтобы потом напечатать, сколько заняли выравнивания.

```python
    pa = pm4py.precision_alignments(X.sample_cases(test, ALIGN_CASES), *models["HM_0.9"])
```
- `X.sample_cases(test, ALIGN_CASES)` — первые 2000 человек из test, те же, что в `test_s`;
- `models["HM_0.9"]` — тройка `(net, im, fm)`: сеть Петри, начальная и конечная разметка;
- `*` распаковывает тройку в три отдельных аргумента, то есть вызов эквивалентен `precision_alignments(log, net, im, fm)`;
- `precision_alignments` ([[04_выравнивания]]) сначала выравнивает каждую трассу с моделью, а потом для каждого префикса трассы смотрит, какие переходы модель разрешает, но в журнале после такого префикса не встречались («убегающие» дуги).

```python
    quality.loc[(quality["model"] == "HM_0.9") & (quality["split"] == "test"), "precision_align"] = round(pa, 4)
```
Результат записывается в новую колонку `precision_align`, только в строку «HM_0.9, test». `.loc[условие, колонка] = значение` создаёт колонку, если её не было. В остальных строках остаётся NaN (пусто).

```python
    print(f"HM 0.9: precision через выравнивания на {ALIGN_CASES} людях = {pa:.4f} ({time.time() - t0:.0f} с)")
```
f-строка: выражения в `{}` подставляются в текст. `:.4f` — 4 знака после запятой, `:.0f` — целые секунды. В твоём запуске вывелось:
`HM 0.9: precision через выравнивания на 2000 людях = 0.8264 (4 с)`.

```python
quality.to_csv(OUT / "model_quality.csv", index=False)
```
Таблица сохраняется в `out\model_quality.csv`. `index=False` — без лишней колонки с номерами строк.

```python
quality[quality["split"] == "test"]
```
Последнее выражение ячейки Jupyter показывает как таблицу. Здесь показываются только строки test, потому что на них и сравниваются модели.

## Что получилось (test)

| модель | fitness | % подходящих трасс | precision (replay) | F1 | позиций / переходов / немых |
|---|---|---|---|---|---|
| HM_0.5 | 0.924 | 65.2 | 0.859 | 0.890 | 58 / 196 / 177 |
| **HM_0.9** | **0.985** | **90.6** | **0.826** (выравнивания 0.826) | **0.898** | 38 / 176 / 158 |
| HM_0.95 | 0.985 | 91.6 | 0.826 | 0.898 | 38 / 176 / 158 |
| IM_0.2 | 0.985 | 85.5 | 0.679 | 0.804 | 56 / 87 / 67 |
| IM_0.5 | 0.935 | 52.4 | 0.703 | 0.803 | 49 / 80 / 60 |

Как читать:
- **HM 0.9 — лучший баланс**: почти все трассы воспроизводятся, и модель разрешает мало лишнего.
- **Precision через выравнивания (0.8264) почти равна replay (0.8259).** Значит, оценкам replay в этом варианте можно доверять.
- **Выравнивания заняли 4 секунды**, а не часы, как на 15 и 29 состояниях. Сеть exp3 маленькая (38 позиций), и в ней мало циклов, поэтому поиск быстрый.
- У IM меньше переходов, но precision ниже: он строит общие циклы («цветок»), в которых разрешено многое.
- **Немых переходов очень много** (158 из 176 у HM 0.9). Так PM4Py переводит heuristics net в сеть Петри: каждая развилка и каждое соединение дуг оформляется немыми переходами. Видимых переходов, то есть состояний, всего 18.

## Почему precision на test выше, чем на train
Например, у HM 0.9 precision 0.746 на train и 0.826 на test. Кажется странным: на test модель должна быть хуже. Но precision считается по префиксам **выборки**: «что модель разрешает после такого начала пути» сравнивается с «что встретилось в этой выборке». Это свойство конкретных 2000 человек, а не переобучение. Fitness на train и test почти одинаковая (0.983 и 0.985), и это главный признак, что переобучения нет.
