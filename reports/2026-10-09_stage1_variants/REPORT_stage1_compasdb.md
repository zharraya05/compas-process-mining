# Этап 1 п. 1.1 на таблице из compas.db: граф переходов

9 октября 2026. Входная таблица: `compas_custody_charges.csv` (собрана `build_from_compas_db.py` прямо из compas.db). Подход тот же, что в прежнем Этапе 1 на данных Даши (`stage1/stage1_multi.py`), поэтому результаты можно сравнивать напрямую.

**Основной вариант с 9 октября: OldCase** (решение Greer). Обвинения по делу, которое у человека уже было в прошлом заключении, считаются старыми. Заключение только из старых обвинений получает состояние OldCase, в остальных заключениях старые обвинения не учитываются. Прежний основной граф, где все обвинения считаются новыми, оставлен для сравнения (раздел 5); прежняя версия отчёта лежит в `prev_report_081026/`.

## 1. Что сделано

По плану (`Repeat (2).pdf`, п. 1.1, Этап 1) и решениям прошлых встреч:

| Понятие | Как задано |
|---|---|
| Объект (case) | человек, `id` = `person_id` из compas.db |
| Событие | заключение под стражу, дата `in_custody` |
| Состояние | множество типов новых обвинений заключения (`crime_categories.py`, 15 типов, см. ниже) или OldCase, если новых обвинений нет. Несколько типов = развилка |
| Старое обвинение | его дело (`case_number`) уже было у этого человека в одном из прошлых заключений |
| Вес дуги | пара (тип эпизода k → тип эпизода k+1) весит 1/(\|S_k\|·\|S_k+1\|), каждый переход в сумме весит 1 |
| Журнал PM4Py | по событию на тип, порядок внутри эпизода случайный (seed 42) |
| Терминал | нет; последнее заключение каждого человека цензурировано концом наблюдения 2016-04-19 |
| Оценка | модели строятся на 80% людей, fitness / precision / потерянные и лишние дуги на 20% |

Код: `stage1_compasdb.py` (журнал, граф, причины, модели), `stage1_common.py` (функции оценки, скопированы из `stage1/stage1_discovery.py`), `compare_and_export.py` (сравнение и Excel).

### Состояние OldCase

Правило подбора обвинений к заключению по аресту (±1 день) находит и повторные аресты по старому делу: тот же `case_number` уже был у человека в прошлом заключении. Пример: id 1, дело 13011352CF10A в заключениях 2013 и 2014 года. Без пометки такой эпизод повторяет старые обвинения и даёт самопереход, за которым нет нового преступления.

| | эпизодов |
|---|---|
| Есть хотя бы одно обвинение по старому делу | 5 743 (52% из 11 136 повторных заключений) |
| Все обвинения по старым делам → {OldCase} | 4 066 (37%) |
| из них найдены по аресту / по прошлому делу / по дате преступления | 3 573 / 487 / 6 |
| Есть и старые, и новые обвинения → только типы новых | 1 677 |
| Обвинений по старым делам | 18 875 из 65 363 |

Это реальные заключения: медиана 126 дней после прошлого освобождения, почти все в jail. Скорее всего, это аресты за нарушение условий освобождения или по ордеру по тому же делу.

Проверено, может ли в старом деле появиться новое обвинение (например, при новом приговоре): в compas.db таких случаев нет. Таблица `charge` хранит один список обвинений на дело, без дат добавления, поэтому повторный арест по делу всегда получает тот же список. Отметок о нарушении условий освобождения (VOP), неявке в суд (FTA) или инцидентах в тюрьме в compas.db тоже нет.

### Склейка jail → prison

В compas.db переход из jail в prison в день освобождения записан двумя заключениями: это приговор по тому же делу, а не новый арест. У Даши таких записей не было. Prison, начатый в день выхода из предыдущего заключения, приклеивается к нему (829 записей), и ещё 7 заключений, начатых в тот же день, что предыдущее. Итого 22 552 заключения → 21 716 эпизодов. Вариант без склейки (`results_nomerge/`, все обвинения новые): граф почти тот же, самопереходы выше на 0.01–0.05.

## 4. Модели PM4Py и качество

Те же модели и тот же протокол, что раньше: Inductive Miner (шум 0, 0.2, 0.5), Heuristics Miner (порог 0.5, 0.9), DFG с отсечением дуг по доле (0.05, 0.10, 0.20). Обучение на 80% людей, оценка на 20%.

Выравнивания (fitness по alignments) для сетей Inductive Miner с таким числом состояний и развилок не досчитываются и за 2.5 часа на модель, поэтому для IM приведена только fitness по token replay; precision и потерянные / лишние дуги посчитаны для всех моделей. Перебор маркировок для подсчёта лишних дуг ограничен 300 000 (иначе сеть HM 0.5 не помещается в память), поэтому для HM 0.5 число лишних дуг — нижняя оценка.

В тестовом логе 175 разных пар «тип → тип» (без OldCase было 162). Доля переходов считается по всем парам соседних событий тестового лога, включая пары внутри одного эпизода.

**Рекомендация: Heuristics Miner 0.9** (`results_oldcase/figures/petri_HM_dep0.9.png`, `heuristics_net_dep0.9.png`). Он теряет меньше 2% переходов, а для следующего этапа (конкурирующие риски) нужны почти все переходы. Самые частые из потерянных: PublicOrder → Fraud, Violent → Justice, Tampering → OldCase, каждая реже 10 раз в тесте. 96% тестовых людей проходят по сети без ошибок. Precision 0.67 заметно выше, чем без OldCase (0.57): развилок стало меньше, и сеть разрешает меньше лишнего. Лишних дуг всего 5, почти все с редким Justice.

Если важнее компактная и точная схема, можно взять Inductive Miner с шумом 0.2 (precision 0.76, F1 0.86), но он теряет 11% переходов, и только 73% людей проходят по нему без ошибок. Heuristics Miner 0.5 с OldCase хуже, чем 0.9: ни одной дуги не теряет, но 36% тестовых людей по сети не проходят (fitness 0.93), видимо, из-за лишних параллельных веток (вывод, отдельно не проверялся).

- Больше половины прежних самопереходов давали повторные аресты по тому же делу. У редких состояний (Fraud, Weapon, Tampering, Conspiracy, Minors) самоповтор почти целиком был из-за старых дел.
