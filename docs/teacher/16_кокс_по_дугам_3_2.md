# Шаг 3.2: модели Кокса по дугам (конкурирующие риски)

Продолжение [[15_кокс_3_1_и_HR]]. В 3.1 событие — **любое** следующее заключение. Но граф процесса состоит из дуг i → j: из какого состояния в какое. Шаг 3.2 спрашивает: какие признаки ускоряют **конкретный переход**, например Property → Drug, а не просто «возвращение».

## 1. Идея: причинно-специфичный риск

Человек, вышедший из состояния i, может «уйти» по нескольким дугам: в j₁, j₂, j₃… Это **конкурирующие риски**: кто первым наступит, тот и случится, и остальные переходы для этого заключения уже не наблюдаются.

Стандартный способ оценить влияние признаков — **причинно-специфичный риск** (cause-specific hazard). Для каждой дуги i → j строится отдельная модель Кокса:

h_ij(t | x) = h₀,ij(t) · exp(β_ij · x)

- берутся все заключения в состоянии i;
- **событие** = следующее заключение было и оно типа j;
- переход в **любой другой** тип и конец наблюдения считаются **цензурой**: «до этого момента в j не перешёл, дальше не знаем».

HR такой модели читается как в 3.1, но для одной дуги: HR > 1 — признак ускоряет **именно этот** переход.

Почему переход в другой тип можно считать цензурой. Человек, севший за Drug, «выбыл» из-под риска перейти в Property. Мы не знаем, когда бы он перешёл в Property, если бы не сел за Drug, поэтому он даёт информацию только «до дня T в Property не перешёл». Это ровно то, что делает цензура. Важно: так оценивается **интенсивность** перехода, а не вероятность «когда-нибудь попасть в j». Вероятности считает CIF (шаг 2.5).

## 2. Код построчно

```python
arc_cox = ST.cox_arcs(R, feats, min_events=MIN_ARC_EVENTS)
```
Внутри:
```python
for s in state_order(R):                       # каждое состояние i
    d = R[R["state"] == s]                     # заключения в i
    dest = d.loc[d["event"] == 1, "next_state"].value_counts()   # куда переходили
    for j, n in dest.items():
        if n < min_events:                     # дуги с < 50 переходами пропускаются
            continue
        y = ((d["event"] == 1) & (d["next_state"] == j)).astype(int)  # событие = переход именно в j
        fs = _usable(d, feats)                 # убрать признаки, постоянные в этом состоянии
        m = CoxPHFitter(penalizer=penalizer).fit(d[fs].assign(T=d["T"], y=y), "T", "y")
```
- `R` — **все** заключения (train + test). Здесь цель — описать эффекты, а не предсказывать, поэтому test не нужен. Зато и C-index по дугам не считается.
- `min_events = 50` — на дуге должно быть хотя бы 50 переходов. Иначе 10 коэффициентов оценивать не на чем.
- `penalizer = 0.05` — регуляризация сильнее, чем в 3.1 (0.01). На маленьких дугах без неё коэффициенты могут «улететь» в бесконечность (например, если на дуге все переходы у мужчин).
- `_usable` убирает признак, у которого внутри состояния нет разброса. Поэтому:
  - **старое дело** есть только на 25 дугах из 35: в состояниях `OldCase: X` оно всегда = 1, и на 10 дугах из них признак выпадает;
  - **фелония** на 34 дугах: в состоянии Unknown (тяжесть неизвестна) фелонии не бывает, и на дуге Unknown → Unknown она выпала.

```python
arc_effects = ST.arc_effects_summary(arc_cox, feats)
```
Сводка по каждому признаку: на скольких дугах HR значимо (p < 0.05) больше 1 и меньше 1, медиана, минимум и максимум HR.

```python
ST.plot_arc_heatmap(arc_cox, feats, FIG23 / "cox_arcs_heatmap.png", "...")
```
Тепловая карта: строки — 35 дуг по убыванию числа переходов (в скобках число), столбцы — признаки, в клетке HR, `*` — значимо. Цвет — log₂ HR от −1 до 1: **красный** — признак ускоряет переход (HR до 2 и выше), **синий** — замедляет (HR до 0.5 и ниже), белый — HR ≈ 1. Логарифм нужен, чтобы HR 2 и HR 0.5 выглядели одинаково ярко, но разного цвета.

### Как читать по признакам

**Балл COMPAS — универсальный ускоритель.** Значимо ускоряет 33 перехода из 35, и ни один не замедляет. HR на дугах 1.04–1.16 на балл. Высокий балл означает «быстрее вернёшься», куда бы ни вёл переход. Балл влияет на **скорость**, но не на **направление**.

**Прошлые заключения** тоже только ускоряют (12 дуг), сильнее всего на повторах: Unknown → Unknown 1.24, Traffic → OldCase: Traffic 1.22, Violent → OldCase: Violent 1.21.

**Мужчина** — 6 дуг, все ускоряют. Сильнее всего PublicOrder → Property (HR 2.13, но дуга маленькая, 78 переходов) и Violent → Drug 1.51.

**Афроамериканец** — 5 дуг, ускоряет. Четыре из пяти выходят из Traffic: Traffic → Traffic 1.37, → Property 1.37, → Drug 1.36, → Violent 1.33. Возможное объяснение: повторные задержания за нарушения ПДД чаще у афроамериканцев (например, из-за частоты остановок полицией). Это гипотеза, данные её не проверяют. В общей модели 3.1 HR = 1.00, то есть эффект не общий, а сосредоточен на дугах из Traffic.

**Другая раса** — 3 дуги, замедляет: Property → OldCase: Property 0.71, Property → Property 0.75, OldCase: Drug → OldCase: Drug 0.69.

**Возраст** разнонаправлен: на 6 дугах старше — медленнее (Traffic → Drug 0.83, OldCase: Drug → OldCase: Drug 0.85), на 2 быстрее (Property → Property 1.13). В общей модели он незначим, потому что эффекты разных знаков гасят друг друга.

**Фелония — самый интересный признак: меняет не скорость, а направление.**
- **Ускоряет повторы того же дела** (7 дуг):

  | дуга | HR |
  |---|---|
  | OldCase: Property → OldCase: Property | **2.58** |
  | OldCase: Drug → OldCase: Drug | 2.40 |
  | OldCase: Other → OldCase: Other | 1.87 |
  | Violent → OldCase: Violent | 1.81 |
  | Drug → OldCase: Drug | 1.62 |
  | OldCase: Violent → OldCase: Violent | 1.56 |
  | Property → OldCase: Property | 1.29 |

- **Замедляет смену типа** (9 дуг):

  | дуга | HR |
  |---|---|
  | OldCase: Property → Property | **0.37** |
  | Property → Drug | 0.51 |
  | Drug → Violent | 0.55 |
  | Property → Violent | 0.58 |
  | Property → Property | 0.59 |
  | Drug → Property | 0.60 |
  | Drug → Traffic | 0.71 |
  | Traffic → Violent | 0.72 |
  | Violent → Violent | 0.755 |

  Толкование: после фелонии дело тяжёлое и длинное, человека снова задерживают **по тому же делу** (суд, нарушение условий, пересмотр). Новые аресты по новым делам после фелонии реже. В модели 3.1 эти эффекты разного знака сложились в умеренное HR 0.90.

  Обрати внимание: Property → Property (новое дело того же типа) фелония замедляет (0.59), а Property → OldCase: Property (то же дело) ускоряет (1.29). Именно для этого и нужно было разделять старые и новые дела в варианте ×2.

**Длительность заключения** тоже разнонаправлена: из новых дел после долгого заключения чуть быстрее возвращаются по старому делу (Violent → OldCase: Violent 1.07), а внутри цепочек OldCase после долгого заключения медленнее (OldCase: Drug → OldCase: Drug 0.87). Вероятно, долгое заключение по старому делу означает, что дело наконец закрыто.

**Старое дело** значимо только на одной дуге (Property → OldCase: Property 0.73), и то с p = 0.049.

## 5. Осторожно

- **Множественные сравнения.** 35 дуг × 10 признаков ≈ 340 проверок. При пороге 0.05 около 17 «значимых» результатов могут оказаться случайными даже если эффектов нет. Поправка (например, Бонферрони: p < 0.05 / 340 ≈ 0.00015 или метод Бенджамини–Хохберга) не делалась. Надёжны **систематические** картины (балл на 33 дугах, фелония с понятным знаком на 16), а одиночные значимые HR на маленьких дугах — только ориентиры.
- Модели построены на всех людях, без test, поэтому это описание данных, а не проверенный прогноз.
- Пропорциональность рисков на дугах не проверялась.
